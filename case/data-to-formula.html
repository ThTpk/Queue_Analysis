2. จับคู่คอลัมน์ — ชื่อของโรงพยาบาล กับ ชื่อที่โค้ดใช้

โรงพยาบาลแต่ละแห่งตั้งชื่อคอลัมน์ไม่เหมือนกัน วิธีแก้คือไม่แก้ชื่อในไฟล์ แต่เขียนตารางแปลงไว้ใน config แล้วให้โปรแกรมอ่านตามนั้น — ไฟล์ดิบยังเป็นต้นฉบับที่ตรวจสอบย้อนได้เสมอ

จุดสำคัญ: ไม่มีบรรทัด start: เพราะไฟล์ไม่มีค่านั้น นั่นคือสาเหตุที่ขั้นที่ 4 ต้องมีอยู่

4. เวลาเริ่มให้บริการ — ค่าที่ไม่มีในไฟล์

ไฟล์บอกว่าคนนี้เข้าคิว 06:11:23 และเสร็จ 06:31:29 รวม 20.1 นาที แต่นั่นคือ "รอ + บริการ" ไม่ใช่เวลาบริการ ถ้าเอา 20.1 ไปเป็น E[S] ตรง ๆ ρ จะพุ่งไป 5 เท่า วิธีแยกคือสร้างคิวย้อนกลับจากเลขโต๊ะ

วิธีที่ 1 — ไล่คิวรายโต๊ะ (วิธีหลัก)

$$\text{start}(n) \;=\; \max\bigl(\text{arrive}(n),\; \text{end}(n-1 \text{ ที่โต๊ะเดียวกัน})\bigr)$$
โต๊ะหนึ่งทำได้คนเดียวต่อครั้ง ฉะนั้นคนถัดไปของโต๊ะนั้นจะเริ่มได้ก็เมื่อ คนก่อนหน้าเสร็จ และตัวเองมาถึงแล้ว — อันไหนช้ากว่าเอาอันนั้น

ถ้าไฟล์ไม่มีเลขโต๊ะ ยังทำได้โดยไล่รวมทั้งหน่วยด้วย $\text{start}(n) = \max(\text{arrive}(n), \text{end}(n-c))$ เมื่อ c คือจำนวนโต๊ะ แต่จะแม่นน้อยลงชัดเจน เพราะไม่รู้ว่าใครไปโต๊ะไหน

ตัวอย่าง — โต๊ะ RE2 ของวันที่ 5 ม.ค.
// แถวที่ไฟล์ให้มา (เรียงตามเวลาเสร็จ) คนที่ 1 arrive 06:05:36 end 06:32:28 คนที่ 2 arrive 06:18:02 end 06:34:51 // วิธีที่ 1 start(1) = max(06:05:36, —) = 06:05:36 ← ยังไม่มีคนก่อนหน้า start(2) = max(06:18:02, 06:32:28) = 06:32:28 ← โต๊ะเพิ่งว่าง service(2) = 06:34:51 − 06:32:28 = 2.38 นาที wait(2) = 06:32:28 − 06:18:02 = 14.43 นาที // ถ้าใช้ end − arrive ทั้งก้อน จะได้ 16.8 นาที // และเข้าใจว่าเป็น "เวลาบริการ" ทั้งหมด → ρ พุ่ง 7 เท่า

ข้อควรระวังที่กินเวลาผมนานที่สุด: เวลาเปิดบริการ

คนที่ 1 ในตัวอย่างข้างบนมาถึง 06:05:36 แต่หน่วยเปิด 06:30 สูตรวิธีที่ 1 จะบอกว่าเขาเริ่มรับบริการ 06:05:36 ทำให้เวลาบริการของเขากลายเป็น 26.9 นาที แทนที่จะเป็น 2.5 นาที — และเพราะคนที่มาก่อนเปิดประตูมีเยอะมาก ความลำเอียงนี้จึงไม่เล็ก

$$\text{start}(n) \;=\; \max\bigl(\text{arrive}(n),\; \text{end}(n-1),\; t_{\text{เปิดบริการ}}\bigr)$$
เพิ่มเวลาเปิดบริการ (06:30) เข้าไปใน max ด้วย

ผลของการเพิ่มพจน์เดียวนี้ วัดได้ชัดที่หน่วยลงทะเบียน ซึ่งเป็นหน่วยแรกที่รับคนที่มายืนรอก่อนเปิด

สิ่งที่หน้านี้พยายามบอก

  • สูตรไม่ใช่ส่วนที่ยาก — Sakasegawa เขียนได้ในสิบบรรทัด แต่การได้ λ, E[S], cv², c ที่เชื่อถือได้จากไฟล์ที่โรงพยาบาลมีอยู่จริง คืองานที่กินเวลาเกือบทั้งโครงการ
  • ค่าที่ไฟล์ไม่มี ต้องประมาณ และต้องรายงานว่าประมาณ — พร้อมความแม่นที่วัดได้ ไม่ใช่เอาค่าประมาณไปวางปนกับค่าที่วัดได้จริง
  • อย่าหยิบ c จากตารางเวร — ในเคสนี้ความต่างระหว่าง 11 กับ 7 คือความต่างระหว่าง "ไม่มีปัญหา" กับ "ไม่มีสมดุล"
  • u กับ ρ ไม่ใช่ตัวเดียวกัน — u ตัดยอดที่ 1 และซ่อนขนาดของปัญหา ส่วน ρ บอกขนาดได้ แต่ต้องมี c ที่ถูก
  • เอาสูตรไปเทียบกับข้อมูลเสมอ — ไม่ใช่เพื่อพิสูจน์ว่าสูตรถูก แต่เพื่อรู้ว่าสูตรหมดสภาพที่ช่วงเวลาไหน
