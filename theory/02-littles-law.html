บทที่ 2

กฎของลิตเติล

สมการสามตัวแปรที่ใช้ได้กับคิวทุกชนิดบนโลก ไม่ว่าคนจะมาแบบไหน บริการนานเท่าไร มีกี่โต๊ะ เรียงคิวอย่างไร — ขอแค่ระบบนิ่งแล้วเท่านั้น

1. ตัวกฎ

$$\boxed{\,L \;=\; \lambda\,W\,}$$
จำนวนงานเฉลี่ยในระบบ = อัตราที่งานไหลเข้า × เวลาเฉลี่ยที่งานหนึ่งชิ้นอยู่ในระบบ

และเพราะมันใช้ได้กับ "ระบบ" อะไรก็ได้ที่เราวาดเส้นรอบไว้ เราจึงใช้กับ เฉพาะส่วนคิว ได้ด้วย

$$L_q \;=\; \lambda\,W_q \qquad\qquad W \;=\; W_q + E[S] \qquad\qquad L \;=\; L_q + c\rho$$
ส่วน $c\rho = \lambda E[S]$ คือจำนวนคนที่กำลังรับบริการอยู่โดยเฉลี่ย

สิ่งที่ทำให้กฎนี้พิเศษ

กฎของลิตเติล ไม่ต้องการสมมติฐานเรื่องการแจกแจงเลย ไม่สนว่าคนมาแบบ Poisson หรือมาเป็นรถบัส ไม่สนว่าเวลาบริการเป็น exponential หรือคงที่ ไม่สนว่าจะ FIFO หรือให้เคสด่วนแซง ขอเพียงระบบ นิ่ง (งานเข้าเท่างานออกในระยะยาว ไม่มีงานค้างสะสมไม่สิ้นสุด) สูตรอื่นทุกสูตรในเว็บนี้ต้องมีสมมติฐาน แต่สูตรนี้ไม่ต้อง

2. ทำไมมันจึงจริง — พิสูจน์ด้วยพื้นที่

ลองวาดกราฟสองเส้นบนแกนเวลาเดียวกัน

  • A(t) = จำนวนคนที่มาถึงสะสม ตั้งแต่เปิดจนถึงเวลา t (เส้นขั้นบันไดขึ้น)
  • D(t) = จำนวนคนที่ออกจากระบบไปแล้วสะสม

ระยะในแนวตั้งระหว่างสองเส้น คือ จำนวนคนที่อยู่ในระบบ ณ ขณะนั้น = L(t)
ระยะในแนวนอนของคนคนหนึ่ง คือ เวลาที่คนนั้นอยู่ในระบบ = W ของคนนั้น

พื้นที่ระหว่างสองเส้นจึงคำนวณได้สองทาง — และต้องได้เท่ากัน

$$\underbrace{\int_0^T L(t)\,dt}_{\text{มองแนวตั้ง}} \;=\; \text{พื้นที่} \;=\; \underbrace{\sum_{i=1}^{N} W_i}_{\text{มองแนวนอน}}$$

หารทั้งสองข้างด้วย T:

$$\bar{L} \;=\; \frac{\text{พื้นที่}}{T} \;=\; \frac{N}{T}\cdot\frac{\sum W_i}{N} \;=\; \lambda \cdot \bar{W}$$

เท่านี้เอง — ไม่มีการแจกแจงเข้ามาเกี่ยวข้องแม้แต่น้อย มันเป็นแค่การนับพื้นที่สี่เหลี่ยมเดียวกันสองวิธี

ห้องทดลอง 2.1 — เห็นพื้นที่นั้นด้วยตาตัวเอง เปลี่ยนจำนวนโต๊ะแล้วดูว่าพื้นที่เปลี่ยนอย่างไร
เปลี่ยนชุดเพื่อดูว่าผลยังตรงกับกฎไหม

3. ใช้ทำอะไรได้บ้าง

3.1 คำนวณขนาดพื้นที่รอ

นี่คือการใช้ที่ตรงไปตรงมาที่สุด และเป็นสิ่งที่ FlowLens คำนวณให้ในคอลัมน์ lq ของตารางวิเคราะห์คิว

ตัวอย่างที่ 2.1 — ต้องมีเก้าอี้กี่ตัวหน้าจุดเจาะเลือด
// สถานการณ์จริงที่เปิด 7 โต๊ะ λ = 1.732 ราย/นาที Wq = 31.4 นาที (เวลารอเฉลี่ยที่วัดได้จริง) Lq = λ × Wq = 1.732 × 31.4 = 54.4 คน → โดยเฉลี่ยมีคนนั่งรออยู่ 54 คน ตลอดช่วงเช้า // ข้อมูลจริงบันทึกไว้ คิว p90 = 88 คน คิวสูงสุด = 140 คน

ค่าเฉลี่ย 54 คนคือสิ่งที่กฎของลิตเติลทำนาย ส่วน p90 = 88 และจุดสูงสุด 140 คือสิ่งที่ ความผันแปร เพิ่มเข้ามา ถ้าออกแบบห้องรอจากค่าเฉลี่ย จะมีคนยืนล้นออกมานอกห้องเกือบทุกเช้า

หลักปฏิบัติ: ออกแบบพื้นที่รอจาก p90 ของจำนวนคิว ไม่ใช่ค่าเฉลี่ย และใช้ค่าเฉลี่ยเพื่อตรวจว่าสมการสมเหตุสมผลเท่านั้น

3.2 ประมาณเวลารอ เมื่อมีแต่จำนวนคน

โรงพยาบาลหลายแห่งไม่มี timestamp ครบ รู้แค่ว่า "เช้านี้คนล้นห้อง" ถ้านับหัวได้และรู้ว่ารับกี่คนต่อชั่วโมง ก็ย้อนหาเวลารอได้ทันที

$$W_q \;=\; \frac{L_q}{\lambda}$$
ตัวอย่างที่ 2.2 — นับหัวตอน 08:00
นับคนนั่งรอหน้าจุดเจาะได้ Lq = 60 คน ช่วงนั้นรับผู้ป่วยเข้ามา λ = 1.73 ราย/นาที Wq = 60 / 1.73 = 34.7 นาที → คนที่เพิ่งเดินเข้าแถวตอนนี้ จะได้เจาะประมาณ 08:35

ตัวเลขนี้แม่นพอจะเอาไปขึ้นจอบอกผู้ป่วยได้เลย และเป็นวิธีที่ FlowLens ใช้ ตรวจไขว้ ความถูกต้องของข้อมูลนำเข้า — ถ้าเวลารอที่คำนวณจาก timestamp ไม่ตรงกับ Lq/λ แปลว่าข้อมูลมีปัญหา

3.3 ดูทั้งระบบเป็นก้อนเดียว

วาดเส้นรอบทั้งห้องแล็บ แล้วใช้กฎเดียวกันกับ TAT (turnaround time) ได้เลย

ตัวอย่างที่ 2.3 — มีผู้ป่วยอยู่ในระบบกี่คน ณ เวลาหนึ่ง
ผู้ป่วยทั้งวัน = 416.45 ราย เวลาเปิด = 06:30–16:30 = 600 นาที λ (เฉลี่ยทั้งวัน) = 416.45 / 600 = 0.694 ราย/นาที TAT เฉลี่ย = 65.9 นาที L = λ × W = 0.694 × 65.9 = 45.7 ราย → เฉลี่ยแล้วมีผู้ป่วย 46 รายอยู่ในกระบวนการพร้อมกัน

แต่เพราะงานกระจุกตอนเช้า ตัวเลขจริงช่วง 08:00 สูงกว่านี้หลายเท่า — อีกครั้งที่ค่าเฉลี่ยทั้งวันหลอกเรา

3.4 ตรวจสอบว่าแบบจำลองถูกต้อง

FlowLens ใช้กฎนี้เป็นด่านตรวจ: หลังรันแบบจำลอง (SimPy) จะเช็กว่า จำนวนคิวเฉลี่ยที่จำลองได้ เท่ากับ λ × เวลารอเฉลี่ยที่จำลองได้หรือไม่ ถ้าไม่เท่า แปลว่าแบบจำลองมีบั๊ก ไม่ใช่ว่าโลกแปลก

ใช้เป็นเครื่องมือตรวจข้อมูลได้ทันที

ถ้ามีคนรายงานว่า "คิวเฉลี่ย 20 คน รอเฉลี่ย 5 นาที รับ 1.7 ราย/นาที" ลองคูณดู: 1.7 × 5 = 8.5 ≠ 20 ตัวเลขชุดนี้เป็นไปไม่ได้ ต้องมีค่าใดค่าหนึ่งผิด — มักเป็นเวลารอที่วัดจากจุดที่ไม่ตรงกับคิวที่นับ

4. ข้อจำกัดที่ต้องระวัง

เงื่อนไขถ้าละเมิดแล้วเกิดอะไร
ระบบต้องนิ่ง (ρ < 1) ถ้า ρ ≥ 1 ทั้ง L และ W โตไม่หยุด ค่าเฉลี่ยไม่ลู่เข้าค่าใด กฎยังจริงเชิงคณิตศาสตร์แต่ใช้ทำนายไม่ได้
ช่วงเวลาต้องยาวพอ ถ้าวัดช่วงสั้น ๆ ที่มีคนค้างอยู่ตอนต้นและตอนท้าย ผลจะเพี้ยน — ยิ่งช่วงสั้นยิ่งเพี้ยนมาก
ขอบเขต "ระบบ" ต้องชัด λ ที่ใช้ต้องเป็นอัตราที่เข้าขอบเขตนั้น ถ้ามีงานทำซ้ำวนกลับ λ ที่แท้จริงของหน่วยนั้นสูงกว่าที่ประตู (ดู บทที่ 6)
มันบอกแค่ค่าเฉลี่ย ไม่บอก p90 ไม่บอกคิวสูงสุด ไม่บอกว่าช่วงไหนแย่ — ต้องใช้สูตรอื่นเสริม (บทที่ 5)

สรุปบทที่ 2

  • L = λW และ Lq = λWq — ใช้ได้กับทุกระบบที่นิ่ง ไม่ต้องรู้การแจกแจง
  • พิสูจน์ได้ด้วยการนับพื้นที่ระหว่างเส้นมาถึงสะสมกับเส้นออกสะสม
  • ใช้แปลง "จำนวนคนในห้องรอ" ↔ "นาทีที่ต้องรอ" ได้ทั้งสองทาง
  • ใช้ออกแบบพื้นที่รอ (แต่ต้องใช้ p90 ไม่ใช่ค่าเฉลี่ย) และใช้ตรวจความสมเหตุสมผลของข้อมูล
  • มันบอกแค่ค่าเฉลี่ย ไม่ได้บอกว่าทำไม — บทต่อไปจะตอบว่า อะไร ทำให้ W ยาว
