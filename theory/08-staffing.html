บทที่ 8

คำนวณกำลังคน

จนถึงบทที่แล้วเราถามว่า "เปิด c โต๊ะ แล้วรอกี่นาที" บทนี้กลับทิศคำถาม: "อยากให้รอไม่เกิน t นาที ต้องเปิดกี่โต๊ะ ช่วงไหน ราคาเท่าไร"

หัวหน้าหน่วยไม่ได้อยากรู้ว่าเวลารอจะเป็นกี่นาที เขาอยากรู้ว่า พรุ่งนี้เช้าต้องจัดคนกี่คน และจัดช่วงไหน ถ้าต้องขอเพิ่ม จะขอเท่าไรจึงจะพอโดยไม่ขอเกินจนถูกตีกลับ

แปดบทที่ผ่านมาถามว่า "เปิดเท่านี้แล้วจะรอกี่นาที" บทนี้กลับทิศคำถาม — ตั้งเป้าที่อยากได้ก่อน แล้วย้อนกลับไปหาจำนวนคน จากนั้นแปลงเป็นตารางกะที่เอาไปติดบอร์ดได้จริง พร้อมราคาต่อวัน

ถ้าอยากได้คำตอบโดยไม่ต้องอ่านสูตร ไปที่ หน้าวางแผนโต๊ะรายช่วงเวลา ได้เลย — เลือกหน่วย ตั้งเป้า แล้วมันคำนวณตารางกะกับค่าใช้จ่ายให้ทันที บทนี้คือคำอธิบายว่าหน้านั้นคิดยังไง

1. สองเกณฑ์ที่ต้องผ่านพร้อมกัน

FlowLens คำนวณจำนวนโต๊ะที่ต้องการจากสองเงื่อนไข แล้วเลือกค่าที่มากกว่า

เกณฑ์ที่ 1 — เพดานการใช้กำลัง

$$c \;\ge\; \left\lceil \frac{\lambda\,E[S]}{\rho_{\max}} \right\rceil$$

รับประกันว่าระบบเสถียรและยังเหลือที่ว่าง ค่าเริ่มต้น ρ_max = 0.85

เกณฑ์ที่ 2 — เป้าเวลารอ

หา c ที่น้อยที่สุดซึ่งทำให้

$$W_q(p{=}0.9) \;\le\; t_{\text{target}}$$

ไม่มีสูตรปิด ต้องไล่ลอง c ทีละค่า จนกว่าจะผ่าน

def min_servers_for_wait(lam, service_mean, target_wait, p=0.9, ca2=1.0, cs2=1.0,
                         rho_max=0.999):
    start = min_servers_for_utilization(lam, service_mean, rho_max)
    for c in range(max(1, start), MAX_SERVERS_SEARCH + 1):
        w = wq_percentile(lam, service_mean, c, p=p, ca2=ca2, cs2=cs2)
        if math.isfinite(w) and w <= target_wait:
            return c
    return MAX_SERVERS_SEARCH

# แล้วเลือกค่าที่เข้มกว่า
staffing["servers_needed"] = staffing[["min_servers_rho", "min_servers_wait"]].max(axis=1)
staffing["gap"]            = staffing["servers_needed"] - staffing["servers"]

เพราะถ้า c น้อยกว่า $\lambda E[S]$ สูตรจะคืนค่า ∞ และวนไปเรื่อย ๆ โดยไม่มีประโยชน์ การเริ่มที่จุดเสถียรทำให้การค้นหาเร็วและปลอดภัย

2. กฎรากที่สอง (square-root staffing)

มีกฎประมาณที่คิดในหัวได้และแม่นอย่างน่าประหลาด สำหรับระบบที่มีหลายโต๊ะ

$$c^{*} \;\approx\; a \;+\; \beta\sqrt{a}, \qquad a=\lambda E[S]$$
a คือกำลังที่ "ต้องมีแน่ ๆ" ส่วน $\beta\sqrt{a}$ คือกันชนสำหรับความผันแปร — เรียกว่า QED regime (Quality and Efficiency Driven)
βระดับบริการโดยประมาณเหมาะกับ
0.0ρ → 1, คิวยาว, ไม่เสถียรไม่ควรใช้
0.5ประมาณครึ่งหนึ่งต้องรองานหลังบ้านที่รอได้
1.0ประมาณ 20–30% ต้องรอบริการผู้ป่วยทั่วไป
1.5ประมาณ 10% ต้องรอบริการที่ต้องเร็ว
2.0น้อยกว่า 5% ต้องรอห้องฉุกเฉิน, งานด่วน
ตัวอย่างที่ 8.2 — คิดในหัวใน 10 วินาที
a = 1.732 × 4.2 = 7.27 √a = 2.70 β = 0.5 → c ≈ 7.27 + 1.35 = 8.62 → 9 โต๊ะ β = 1.0 → c ≈ 7.27 + 2.70 = 9.97 → 10 โต๊ะ คำตอบจากสูตรเต็ม (ρ ≤ 0.85) = 9 โต๊ะ → ตรงกับ β = 0.5 พอดี ส่วน β = 1.0 เผื่อไว้มากกว่าหนึ่งโต๊ะ

กฎนี้ใช้สื่อสารกับผู้บริหารได้ดีมาก เพราะอธิบายได้ว่า "งานต้องการ 7.3 โต๊ะ บวกกันชนอีก 2.7 โต๊ะสำหรับความไม่แน่นอน" แทนที่จะชี้ไปที่ผลลัพธ์ของสูตรที่ไม่มีใครเข้าใจ

การประหยัดต่อขนาด — ทำไมหน่วยใหญ่ได้เปรียบ

กันชนโตตาม $\sqrt{a}$ ไม่ใช่ตาม a แปลว่ายิ่งหน่วยใหญ่ ยิ่งต้องการกันชนเป็นสัดส่วนน้อยลง

นี่คือเหตุผลเชิงคณิตศาสตร์ว่าทำไมการรวมหน่วยเล็กเข้าด้วยกัน ถึงประหยัดได้จริง และทำไมเครื่องเคมีคลินิก 20 เครื่องจึงรับงานได้ที่ ρ = 0.81 โดยคนไข้แทบไม่ต้องรอ ขณะที่จุดเจาะเลือด 7 โต๊ะที่ ρ = 1.00 พังสนิท

5. จากจำนวนโต๊ะ สู่ตารางกะที่ใช้ได้จริง

ตารางรายช่วง 15 นาทีบอกว่า "ต้องการ 9 คน ตอน 07:00 และ 4 คน ตอน 11:00" แต่เราจ้างคนเป็นกะ ไม่ใช่เป็นช่วง 15 นาที การแปลงจากความต้องการรายช่วงเป็นตารางกะ คือปัญหา set covering ซึ่งแก้ด้วย integer programming

$$\min \sum_{s} k_s\,\text{cost}_s \qquad\text{s.t.}\qquad \sum_{s \ni b} k_s \;\ge\; \text{need}_b \;\;\forall b, \qquad k_s \in \mathbb{Z}_{\ge 0}$$
$k_s$ = จำนวนคนที่เข้ากะแบบ s · $s \ni b$ หมายถึงกะ s ครอบคลุมช่วงเวลา b

FlowLens แก้ปัญหานี้ในโมดูล analysis/staffing.py แล้วออกมาเป็นตารางกะพร้อมใช้ ส่งออกเป็น Excel ให้หัวหน้าหน่วยได้ทันที

ข้อควรระวัง: SIPP และกับดักของการคำนวณรายช่วง

วิธีที่ใช้ในบทนี้เรียกว่า SIPP (Stationary Independent Period by Period) — สมมติว่าแต่ละช่วง 15 นาทีเป็นระบบคิวอิสระที่นิ่งแล้ว สมมติฐานนี้ผิดเมื่อคิวจากช่วงก่อนไหลมาถึงช่วงนี้ ซึ่งเป็นสิ่งที่เกิดขึ้นทุกเช้าในกรณีศึกษา วิธีแก้ที่รู้จักกันดีคือ Lag SIPP (เลื่อนช่วงที่ใช้คำนวณไปข้างหน้า ประมาณหนึ่งเท่าของเวลาบริการ) แต่ทางที่ตรงที่สุดคือจำลองทั้งวัน ซึ่งเป็นเรื่องของบทถัดไป

สรุปบทที่ 8

  • จำนวนโต๊ะที่ต้องการ = ค่าที่มากกว่า ระหว่างเกณฑ์ ρ กับเกณฑ์เวลารอ
  • เกณฑ์เวลารอไม่มีสูตรปิด ต้องไล่ลอง c ทีละค่า เริ่มจากจุดที่เสถียร
  • c ≈ a + β√a — คิดในหัวได้ และอธิบายให้ผู้บริหารเข้าใจง่ายที่สุด
  • กันชนโตตาม √a ไม่ใช่ a → หน่วยใหญ่ได้เปรียบเสมอ
  • ต้องคำนวณรายช่วงเวลา แล้วค่อยแปลงเป็นกะด้วย integer programming
  • SIPP ใช้ได้ดีเมื่อไม่มีคิวค้างข้ามช่วง — ถ้ามี ต้องใช้ Lag SIPP หรือการจำลอง
